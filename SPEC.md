## 1. Executive Summary

This document specifies a complete, private rebuild of the Spine Canvas / Swarm product surface: an infinite canvas on which typed blocks are generated by AI agents, wired together as a directed acyclic graph (DAG), and executed as runs that emit real downloadable artifacts (.docx, .xlsx, .pptx, .png, .html). The rebuild targets a single-user deployment, which materially simplifies the platform: billing, plan enforcement, and tenant isolation collapse into local accounting and a single-owner row-level security policy, while the interesting engineering — DAG execution, cascading re-runs, multi-tier agent orchestration, and multi-provider model routing — is preserved in full.

### 1.1 What is being rebuilt
* An infinite canvas workspace where every artifact is a typed block, and every dependency is an explicit edge — mapping 1:1 onto React Flow's node/edge model [3].
* A run engine that accepts a natural-language prompt plus constraints (template, allowed_block_types, agent_instructions) and materialises a block graph as output, tracking status, estimated_duration_ms, and credits_consumed per run [1] [5].
* A block library spanning 17 API-addressable block types plus 5 app-only container/UI block types (Chat, Frames, Inputs, Folder, Folder Synthesis) [2].
* Swarm Mode: a hierarchical task tree (tier / persona / agent_tier / parent_task_id) where an L1 conversational orchestrator plans, and lower tiers create and fill blocks [1] [2] [5].
* A cascading re-run engine: when an upstream block's content changes, descendants are invalidated and re-queued via topological traversal of the edges table plus Supabase Realtime postgres_changes subscriptions [3].
* An outbound integration and MCP layer: OAuth connectors persisted in an integrations table, plus a first-party MCP server built on the official TypeScript SDK [1] [3] [5].

### 1.2 What is deliberately out of scope
* Multi-tenant billing, subscription webhooks, and plan upgrade flows. The users table retains plan, monthly_credits, daily_bonus_credits, and credit_pack_balance columns for schema fidelity, but they are used only as local spend telemetry [1] [5].
* Team/workspace sharing, roles, and invitations. RLS is a single-owner predicate.
* Horizontal worker fleets. Long-running block generation uses Vercel serverless/background functions with a Postgres-backed queue rather than a dedicated worker cluster.

Critical grounding caveat: every row in the proposed Postgres schema research table is flagged confidence = Inferred, derived from the public canvases-and-runs API concepts documentation rather than from the production DDL [1] [5]. Treat the schema in Section 3 as a high-fidelity working model, and validate column names against live API payloads during Phase 1 before writing migrations that are expensive to reverse.
